# Web前端开发方法论

## 一、概述

### 1.1 这是什么

Web前端开发领域的系统性方法论，涵盖认知标准、结构分析、因果理解、质量检查、价值决策和沟通协作的完整思维体系。

### 1.2 适用范围

- ✅ 浏览器环境下的Web应用开发
- ✅ React/Vue/Angular等主流框架
- ✅ 工程化工具链和性能优化
- ❌ 原生移动应用开发
- ❌ 后端服务开发
- ❌ 桌面应用（Electron除外）

### 1.3 核心原则

1. **用户功能可用优先** —— 功能完整比性能完美更重要
2. **测量先于优化** —— 不确定时先建立基线
3. **渐进式增强** —— 基础功能优先，高级特性渐进添加
4. **可维护性长期价值** —— 短期hack要记录债务

## 三、核心原则

### 3.1 认知标准

**可靠知识来源**（按优先级）：
1. MDN + W3C规范 ⭐⭐⭐⭐
2. 源代码验证 ⭐⭐⭐⭐
3. 框架官方文档 ⭐⭐⭐
4. TypeScript类型 ⭐⭐⭐
5. 社区文章（需交叉验证）⭐⭐

**常见认知陷阱**：
- "能跑就行" —— 绕过框架机制
- 框架依赖盲区 —— 不理解底层原理
- 过早优化 —— 未测量就优化
- 视觉即正确 —— 忽视可访问性

### 3.2 结构分析

**核心实体**：组件、状态、路由、资源、副作用、用户事件

**问题分解维度**：
- 按架构层次：表现层 → 组件层 → 状态层 → 副作用层 → 工程层 → 体验层
- 按用户旅程：首次加载 → 交互响应 → 数据获取 → 页面切换

### 3.3 因果理解

**核心因果链**：
- 状态变化 → 重新渲染 → DOM更新
- 大数据集 → 主线程阻塞 → 交互卡顿
- 代码分割 → 按需加载 → 首屏缩短

**正反馈（需打破）**：代码质量差 → 修改困难 → 更多hack
**负反馈（维持质量）**：代码提交 → 审查 → 修复 → 合并

### 3.4 价值层级

1. 用户功能可用（最高）
2. 正确性
3. 性能体验
4. 可维护性
5. 开发效率
6. 技术先进性（最低）

生成的L3 SKILL.md 必须包含：

```yaml
---
```

**正文结构**：

4. **示例** —— 代码/配置示例
5. **常见问题** —— 错误处理和边缘情况
6. **相关技能** —— 链接到其他L3或本L2

### 4.4 生成示例

**示例：生成"React表单处理技能"**

**步骤1：确定触发条件**
- 用户需要处理表单输入
- 需要验证、提交、错误处理

**步骤2：提取相关原则**
- 从"结构分析"提取：状态管理（受控组件）、副作用（表单提交）
- 从"认知标准"提取：验证标准（必须验证输入）
- 从"价值决策"提取：用户功能可用 > 开发效率

**步骤3：构建L3结构**
- 概述：React表单处理的最佳实践
- 前置条件：熟悉React基础、了解受控组件
- 执行步骤：
  1. 设计表单状态结构
  2. 实现受控输入
  3. 添加验证逻辑
  4. 处理提交和错误
- 示例：代码示例
- 常见问题：验证时机选择、异步提交处理

**步骤4：输出为SKILL.md**

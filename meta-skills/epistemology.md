# 认识论框架（Epistemology）

## 一、本元元技能是什么

认识论框架是关于"如何评估知识的可靠性"的元认知体系。

它不直接参与Agent的日常推理和决策。它的唯一职责是：**当Agent需要为一个新领域构建或修订L2方法论时，确保该方法论在认知层面是完备的、自洽的、有边界的。**

简单说：它教Agent"怎么为一个新领域建立靠谱的认知标准"。

## 二、核心认知原则

以下是本框架的底层信念体系，L2生成时必须将这些原则"翻译"到具体领域。

### 2.1 知识状态三分法

任何领域的任何命题，只可能处于三种状态：

| 状态 | 定义 | 特征 |
|------|------|------|
| **确定知道** | 有充分证据支持，经得起验证 | 可以作为推理的坚实基础 |
| **确定不知道** | 明确超出认知边界或信息不足 | 必须承认，不能伪装成知道 |
| **以为知道** | 有一定证据但不足以确信，或存在未察觉的偏差 | 最危险的状态，是大部分错误的来源 |

核心命题：**"以为知道"是认知失败的主要来源。好的方法论必须能识别和管理这个状态。**

### 2.2 证据等级体系

所有领域的知识都可以按证据强度分级。以下是通用等级（L2生成时需映射到领域具体实例）：

等级5：形式化证明 / 逻辑必然 特征：在给定前提下，结论不可能为假 示例：数学定理、形式验证通过的程序性质

等级4：强经验验证 特征：经过严格的、可重复的验证 示例：实验复现、自动化测试通过、实测数据

等级3：可信来源背书 特征：来自权威或共识性来源，但未经亲自验证 示例：官方文档、标准规范、领域经典文献

等级2：合理推断 特征：基于已知信息进行逻辑推导，逻辑链清晰但未直接验证 示例：根据文档推断的API用法、类比推理

等级1：弱信号 / 直觉 特征：模式匹配、经验直觉、不完整信息下的猜测 示例："之前见过类似的"、直觉判断

等级0：无依据 特征：没有实质性证据 示例：凭空猜测、无来源的断言


核心命题：**不同决策场景对证据等级有不同要求。好的方法论必须明确每个关键步骤所需的最低证据等级。**

### 2.3 不确定性管理原则

当知识不足时，不是"不能行动"，而是"按原则行动"：

原则一：信息缺口识别 先判断"我缺什么信息"，而不是直接跳到结论

原则二：最坏后果评估 做错了最坏会怎样？后果决定需要多高的证据等级

原则三：梯度响应 后果轻微 → 可用低等级证据行动，标注不确定性 后果严重 → 必须提升到高等级证据，否则停下来

原则四：安全默认 不确定时，选择风险最低的行动路径 不存在安全默认时，向用户坦白并请求决策


### 2.4 知识边界原则

**好的方法论必须知道自己不能做什么。** 每个L2都必须明确声明：

- 适用范围：这个方法论在什么条件下有效
- 不适用范围：什么情况下不应该使用这个方法论
- 退化条件：当条件不完全满足时，方法论的哪些部分仍然可用

### 2.5 反面模式（认知红线）

以下是所有领域都应避免的认知错误，L2生成时必须检查是否已覆盖：

| 反面模式 | 本质 | 在方法论中的应对 |
|---------|------|----------------|
| 自信的胡说 | 用确定语气表达不确定内容 | 必须有置信度标注机制 |
| 忽视矛盾 | 遇到矛盾信息选择性忽略 | 必须有矛盾检测和处理流程 |
| 过度泛化 | 从个案推广到普遍规律 | 必须区分"已验证"和"推测" |
| 事后合理化 | 先有结论再找证据 | 证据收集必须在结论之前 |
| 证据筛选 | 只看支持自己立场的证据 | 必须主动寻找反对证据 |
| 假装知道 | 不愿承认不知道 | 必须有"停下来承认不知道"的触发条件 |

## 三、权威资料搜索要求（新增）

### 3.0 强制搜索步骤

**在生成L2方法论之前，Agent必须通过网络搜索获取该领域的权威资料。**

#### 搜索目标

| 资料类型 | 搜索关键词示例 | 最低数量 |
|----------|---------------|----------|
| **学术论文** | "[领域] best practices survey"、"[领域] systematic review" | 2-3篇 |
| **行业标准/规范** | "[领域] standard specification"、"[领域] RFC" | 1-2份 |
| **权威书籍/经典著作** | "[领域] definitive guide"、"[领域] classic book" | 1-2本 |
| **领域专家观点** | "[领域] expert consensus"、"[领域] thought leaders" | 2-3个来源 |

#### 搜索执行时机

**搜索必须在3.1-3.6各步骤之前进行**，作为知识来源的基础输入：

```
开始生成L2
  │
  ▼
【强制】网络搜索权威资料
  │
  ├──→ 搜索学术论文
  ├──→ 搜索行业标准
  ├──→ 搜索经典著作
  └──→ 搜索专家观点
  │
  ▼
整合搜索结果到知识库
  │
  ▼
执行3.1-3.6生成引导（基于搜索资料）
```

#### 搜索质量要求

**必须记录的信息**：
- 搜索使用的具体关键词
- 找到的资料标题和作者/机构
- 资料发布年份（优先近5年，经典除外）
- 资料可信度评估（为什么认为权威）

**搜索失败处理**：
- 如果某类资料搜索不到 → 在3.1中明确标注"该领域缺乏[某类]权威资料"
- 如果搜索结果被判定为不可靠 → 说明理由并继续搜索替代来源
- 如果完全无法找到任何权威资料 → **停止生成**，向用户报告"该领域知识基础不足，无法生成可靠方法论"

#### 资料整合要求

搜索到的权威资料必须整合到后续生成步骤中：

| 生成步骤 | 如何使用搜索资料 |
|----------|-----------------|
| 3.1 知识来源清单 | 将搜索到的资料作为高等级来源 |
| 3.2 来源可靠性映射 | 评估搜索资料的证据等级 |
| 3.3 认知陷阱识别 | 参考论文中提到的常见错误 |
| 3.5 验证标准 | 借鉴行业标准中的验证方法 |

## 四、L2生成引导

这是本元元技能的核心部分。当Agent在L2生成流程中调用"认识论框架"时，以下内容将作为**强制检查项**注入生成过程。

**注意：以下引导假设已经完成了3.0的权威资料搜索**。

每一条引导包含：引导问题、输出要求、质量标准。

### 4.1 领域知识来源清单

**引导问题：**
> "基于权威资料搜索的结果，在这个领域中，Agent获取知识的来源有哪些类型？请完整列举。"

**输出要求：**
- 列出该领域所有主要知识来源类型（不少于3种）
- **必须包含3.0搜索到的权威资料作为高等级来源**
- 每种来源给出一句话描述和典型场景
- **标注哪些来源来自3.0的搜索结果**

**质量标准：**
- ✅ 覆盖了该领域最核心的信息渠道
- ✅ **包含搜索到的学术论文、标准规范等权威资料**
- ✅ 没有明显遗漏（如软件开发领域漏掉"代码本身"就算不合格）
- ❌ 仅列出1-2种来源视为不通过
- ❌ **未使用3.0搜索结果视为不通过**

### 4.2 来源可靠性映射

**引导问题：**
> "在列出的知识来源中，每种来源在这个领域的可靠性如何？3.0搜索到的权威资料应如何评级？"

**输出要求：**
- 为每种来源标注证据等级（映射到通用等级体系）
- **优先评估3.0搜索到的权威资料的可靠性**
- 明确标注该领域特有的"高误导来源"并说明原因
- 标注来源可靠性的时效性（某些来源多久会过时）

**质量标准：**
- ✅ 每种来源都有明确的等级标注和理由
- ✅ **搜索到的学术论文、标准规范应评为高等级（3-4级）**
- ✅ 至少识别出一个该领域特有的"易误导来源"
- ✅ 时效性标注覆盖快速变化的来源
- ❌ 所有来源都标为同样等级视为不通过

### 4.3 领域认知陷阱识别

**引导问题：**
> "基于3.0搜索到的资料，在这个领域中，从业者（或Agent）最容易犯的认知错误是什么？"

**输出要求：**
- 列出至少3个该领域特有的认知陷阱
- **优先参考学术论文中提到的常见错误**
- 每个陷阱包含：名称、描述、真实或假设案例、防范方法
- 将每个陷阱映射到2.5节的通用反面模式
- **标注哪些陷阱来自搜索资料的发现**

**质量标准：**
- ✅ 陷阱必须是该领域特有的（不能只是通用错误的复制粘贴）
- ✅ **至少1个陷阱应来自3.0搜索的权威资料**
- ✅ 每个陷阱都有具体的、可执行的防范方法
- ✅ 有案例说明（即使是假设的）
- ❌ 仅有名称没有描述和防范方法视为不通过

### 4.4 知识边界声明

**引导问题：**
> "基于3.0搜索到的资料，这个方法论能解决什么问题？更重要的是，它明确不能解决什么问题？"

**输出要求：**
- 明确的适用场景列表
- 明确的不适用场景列表（至少2条）
- **参考行业标准中定义的范围边界**
- 退化条件：当条件不完全满足时哪些部分仍可用

**质量标准：**
- ✅ 不适用场景是真诚的、有价值的（不能写"不适用于完全无关的领域"这种废话）
- ✅ **边界声明应与搜索到的标准规范一致**
- ✅ 退化条件有实际指导意义
- ❌ 没有"不适用场景"段落的L2视为不通过

### 4.5 领域验证标准

**引导问题：**
> "基于3.0搜索到的资料，在这个领域中，怎么判断一个结论或输出是正确的？"

**输出要求：**
- 列出该领域可用的验证手段（每种对应一个证据等级）
- **优先借鉴行业标准、学术论文中的验证方法**
- 为方法论中的关键结论定义最低验证要求
- 明确哪些验证是必须的（不可跳过），哪些是推荐的

**质量标准：**
- ✅ 验证手段覆盖从快速到完整的梯度
- ✅ **至少1种验证方法应来自3.0搜索的权威资料**
- ✅ 关键结论有明确的最低验证门槛
- ✅ 区分了"必须验证"和"建议验证"
- ❌ 没有"必须验证"项的视为不通过

### 4.6 不确定性处理策略

**引导问题：**
> "这个领域最常见的两种不确定性是什么？各自应该怎么处理？"

**输出要求：**
- 识别至少2种该领域典型的不确定性场景
- 每种场景给出具体的处理策略（映射到2.3节的原则）
- **参考权威资料中推荐的处理方法**
- 定义什么情况下应停下来向用户请求决策

**质量标准：**
- ✅ 不确定性是具体的、领域相关的（不能只写"信息不足"）
- ✅ 每种不确定性都有可执行的处理策略
- ✅ 有明确的"停下来请求帮助"的阈值
- ❌ 笼统回答"遇到不确定就问用户"视为不通过

## 五、L2质量审核标准

当一个L2方法论声称已经遵循了"认识论框架"元元技能，用以下清单进行审核。全部通过才能标注为"认识论合规"。

### 必须通过项（任一不通过则整体不通过）

| 编号 | 审核项 | 检查方式 |
|------|--------|---------|
| E-00 | **是否完成了3.0的权威资料搜索？** | 检查搜索记录和资料列表 |
| E-01 | 是否包含领域知识来源清单且覆盖主要渠道？ | 检查4.1的输出 |
| E-02 | 每种来源是否有可靠性标注且等级有差异？ | 检查4.2的输出 |
| E-03 | 是否识别了至少3个领域特有认知陷阱且有防范方法？ | 检查4.3的输出 |
| E-04 | 是否有明确的不适用场景声明？ | 检查4.4的输出 |
| E-05 | 是否定义了关键结论的最低验证要求？ | 检查4.5的输出 |
| E-06 | 是否有至少2种领域不确定性的具体处理策略？ | 检查4.6的输出 |
| E-07 | 整体是否有置信度标注机制（不说所有内容都一样确定）？ | 通读全文检查 |

### 推荐通过项（不通过不阻塞，但标记为待改进）

| 编号 | 审核项 | 说明 |
|------|--------|------|
| E-R00 | **搜索到的权威资料是否充分（≥5个来源）？** | 资料越多方法论越可靠 |
| E-R01 | 是否有来源时效性标注？ | 快速变化领域此项应升为必须 |
| E-R02 | 认知陷阱是否有真实案例？ | 没有案例也可以，但有了质量更高 |
| E-R03 | 是否有退化条件？ | 即方法不完全适用时怎么办 |
| E-R04 | 验证手段是否有梯度（从快到完整）？ | 提升方法论的实用性 |
| E-R05 | **搜索资料是否来自多样化来源（论文+标准+专家）？** | 单一来源类型可能有偏见 |

### 审核结果标签

全部必须项通过 + ≥3推荐项通过 → 标记为"认识论合规·优秀" 全部必须项通过 + <3推荐项通过 → 标记为"认识论合规·合格" 任一必须项不通过 → 标记为"认识论不合规·需修订"

## 六、与其他元元技能的协作关系

本元元技能在L2生成流程中的角色定位：

L2生成流程中的调用顺序（建议）：

```
[认识论框架] ─── 第一个被调用
  │
  ├──→ 【3.0 强制步骤】网络搜索权威资料
  │       └── 输出：学术论文、行业标准、经典著作、专家观点
  │
  ├──→ 【4.1-4.6】基于搜索资料建立认知标准
  │       └── 输出：知识来源清单、可靠性映射、认知陷阱...
  │
  ▼
[分解与抽象] ─── 在认知标准明确后，分解领域结构
  │
  ▼
[因果与系统思维] ── 在结构清晰后，建立因果模型
  │
  ▼
[元认知] ─── 审视前几步是否有认知偏差
  │
  ▼
[价值与优先级] ── 确定该领域的价值排序
  │
  ▼
L2输出 → 质量审核（再次调用各L1的审核标准）
```

认识论框架排在第一位，因为**"怎么判断对错"是构建方法论的地基**。如果一个领域连"什么是好的证据"都没定义清楚，后面的分解、因果、优先级都建立在沙子上。

**3.0的搜索步骤是认识论框架的核心新增**，确保L2建立在权威资料基础上，而非仅依赖Agent的训练数据。
